Start with your coding agent

Atlas turns a coding agent’s repository findings into an interactive architecture map. It works with web applications, APIs, mobile and desktop software, command-line tools, libraries, infrastructure and mixed projects.

  1. Open Atlas and choose Copy agent prompt.
  2. Paste the prompt into the coding agent already working in your repository. Give that agent the repository access you intend it to have.
  3. When asked, choose the delivery mode and a dedicated Atlas output folder. Manual mode produces a map from the evidence available at that moment; automatic delivery uses the helper workflow described in the prompt.
  4. Open the generated Atlas link, or use Import architecture to paste or select its JSON file.
  5. Select components and check their descriptions, relationships, source references and uncertainty against the actual project.

Atlas does not inspect your source code. Your chosen coding agent does that work. Its permissions, cost and data handling are separate from Atlas. Only put information you are comfortable storing or sharing into the map.

To explore first, open the fictional sample map. It contains no customer or repository data.

Find your way around

  • Mouse: drag empty map space to pan, use the wheel to zoom, and drag a component card to reposition it.
  • Touch: drag with one finger to pan, even when starting on a card or a connection. Pinch with two fingers to zoom. Touch navigation does not move saved component positions.
  • Search: find a component by name and select a result to move smoothly to it. Ctrl+K focuses search on supported desktop keyboards.
  • Fit: brings the current map into view. The + and − controls change zoom.
  • Component types: use the filter chips to highlight or filter the parts you need. Explore offers additional relationship and group navigation.

Details and full screen

Select a card to read its information. On phones, details appear in a short bottom panel; use its expand control when you need more reading space. Close it with its X or tap empty map space.

The full-screen control beside Map and Timeline gives the graph more room while keeping search, categories and layout tools available. The latest pan and zoom carry between normal and full-screen views. Use the control again, or Escape when no higher-priority dialog is open, to return.

Map and Timeline

Map shows the system as connected components. Timeline arranges dependency steps for reading a flow. Its step numbers describe dependency order, not dates or measured execution time.

Organize with category frames

A category is a meaningful group such as Channels, Processing or Data. Components with the same category name can sit in one frame. A category may contain one component or many; components without a category remain outside frames.

Use the optional Category field when adding or editing a component. An agent can provide category names when repository evidence supports them. Category frames are an optional map presentation, not a requirement for every workflow.

Turn on Category frames to see grouped components. Inside a frame, actual component connections remain visible. Relationships crossing between frames share boundary wiring, so several real connections can be represented by one labeled trunk. Select a shared connection to inspect the original relationships.

Drag a category header with a mouse to move its members together. Focused headers also support arrow-key movement. Use Auto layout when you want Atlas to recalculate placement; moving frames does not change what the components mean.

Choose local or cloud storage

Local Workspace

Local maps are saved in this browser without an account. They belong to this site’s browser storage, not a folder on your computer. Another browser profile, another browser, a different site address or a cleared storage area can show a different library.

Tabs using the same site and browser storage can synchronize local changes automatically. If an edit conflicts, Atlas protects an independent recovery copy rather than silently overwriting it.

Cloud Workspace

Google sign-in gives access to maps saved to your Atlas account. Signing in alone does not upload existing local maps. You can deliberately move a map to Cloud Workspace, import into the cloud destination, or enable saving future maps online in Settings.

Check the sidebar destination before importing. An import opened in Cloud Workspace is intended for that account; an import opened in Local Workspace stays in this browser. Account limits are shown by the application and are separate from local storage.

Cloud saving needs a working connection. If a save fails, follow the displayed retry or recovery actions and keep a JSON copy of important work. A saved map and a pending local edit are different states.

Back up, export and restore

ActionWhat it keeps
Backups → Back up mapsA single JSON file containing this browser’s local workspace maps. It does not collect your cloud library.
Export → JSONA portable copy of the current map, including a cloud map you have opened and can export.
Restore backupPreviews the file and restores maps as local copies. Existing maps are not replaced by this action.

Image and SVG exports are useful for presentations. Keep JSON when you need to reopen and edit the map.

Export before clearing site data. Local maps, recovery drafts and browser-stored checkpoints can be lost when the browser removes them. Downloaded files are under your control. A library backup is not a backup of account permissions, cloud upload preferences or the checkpoint database.

Update a map and keep checkpoints

Use Map tools → Update map to apply a new version to the current map. Paste JSON or select a file; valid input opens a change preview. Review additions, removals and edits before applying it. Stable component IDs let Atlas recognize the same component across versions. The position option lets you retain existing placement where supported.

A checkpoint is an explicitly saved snapshot you can name, review, restore, export or remove. Click its row or Review to open the comparison before choosing Restore checkpoint. Restoring one checkpoint does not remove another saved checkpoint.

Checkpoints are stored in this browser, including checkpoints made while editing a cloud map. Cloud checkpoints are scoped to that map and account; they are not a synchronized cloud version-history service. They can survive a normal refresh or browser restart while storage remains intact. Export important versions separately, because browser storage and checkpoint capacity are limited.

Undo and Redo are session history. Do not rely on them after a refresh or closing the browser. Use saved checkpoints or JSON copies when you need a version later.

Share the right kind of link

Local snapshot links

A local share link contains an encoded snapshot of a map. The recipient opens an independent copy. Later changes to your map do not update that copy, and deleting your local original cannot revoke a link or a file someone already has.

Live cloud links

A shared cloud link opens the current saved cloud map for reading. The owner controls edits and can stop sharing or delete the cloud map. Anyone with an enabled link can view its contents; it is not a private invitation system.

Stopping sharing prevents future authorized reads through that link. It cannot remove screenshots, downloads or copies a recipient already made. Never include credentials, API keys or information you are not allowed to share.

Use the hosted Atlas address for links you send to other people. A localhost address refers to the recipient’s own device and normally cannot open your computer’s development server.

When something does not work

The website keeps loading.

On a slow connection, the small startup indicator stays visible until the page controls are ready. If an essential script fails, Retry reloads the same address. Continue to page removes the indicator so you can read what is available; it does not repair a failed script. If needed, open Atlas in a regular browser and check your connection or extension settings. Do not clear site data as the first troubleshooting step.

My local maps are missing.

Check that you are using the same browser, profile and site address as before, and that Local Workspace is selected. Localhost and the hosted website do not share storage. If site data was removed, restore a downloaded JSON backup. Atlas cannot recover a local map that was removed from your browser without a surviving copy.

A save or cloud request failed.

Keep the current tab open, check its save status and use the offered retry or draft-recovery action. Download JSON before navigating away if you are unsure a change reached the cloud. Do not assume a faded loading state or a completed sign-in means a map was uploaded.

Google sign-in does not open or finish.

Allow the sign-in popup for Atlas and try a regular browser tab if you are using an embedded browser. Close a cancelled popup before retrying. You do not need to sign in to use local maps.

My map is crowded or too small.

Try full screen, search for a component, narrow the type filters or trace a specific relationship. Use meaningful categories when they fit the project, and Auto layout to recalculate positions. Large maps still benefit from focused views rather than showing every detail at once.

A shared cloud map no longer opens.

The owner may have stopped sharing or deleted the map, or the network request may have failed. Ask the owner for the current link. Local snapshot links and exported files are independent copies and do not use live cloud permissions.
