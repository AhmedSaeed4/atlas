Map your project in three steps.

Start with the coding agent already working in your repository. Bring its findings into Atlas to explore the system.

01

Create the map

Give your coding agent the Atlas prompt. It checks the repository and maps the components and connections it can support with evidence.

02

Follow the connections

Open the generated map. Select a component, trace its relationships, and use search to find your way through the system.

03

Save or share

Keep the map in this browser, export a JSON backup, or share an interactive link when you are ready to explain the project.

Your project map stays yours.

Use Atlas locally without an account. Cloud saving and live sharing are optional, and stay under your control.

Local to this browser

Maps and edits stay in this browser by default. Signing in does not upload them. You can move a map to your account, or enable cloud saving for future maps in Settings. Existing local maps stay here until you move them. Atlas never uploads repository files.

Back up when you need to

Export a JSON backup before clearing browser storage. Import it later to reopen your map here or in another browser. You decide where the file goes.

Share intentionally

Share a local snapshot or enable a live, view-only cloud link. Anyone with an enabled link can read its contents. Only you can edit the cloud map, and you can stop sharing or delete it.

Agent access is separate. Your coding agent's own data handling applies. Atlas does not read your repository and has no analytics or AI service.
