# Atlas architecture

Atlas is a static website built with HTML, CSS and JavaScript modules. Local mode has no runtime package dependency. The optional Firebase client is built into a locally hosted bundle and loaded only for online actions or viewing an online link.

## Files

- public/index.html, public/landing.css and public/src/landing.js provide the landing page, existing introduction, account panel and prompt flow. public/landing-network.css and public/src/landing-network.js contain its scoped fictional 3D point-network illustration, relationship model and canvas camera controls. Resize-only circular framing and uniform perspective keep the geometry rigid; pointer focus changes node/edge highlight weights instead of point positions or camera angles. The sparse connected mesh has explicit layer-to-component paths, local neighbourhood highlights and depth fading. The reading columns stack above the globe below 780px. Rendering settles while hovered/paused and suspends offscreen. It does not access saved maps. public/landing-scene.css and public/src/landing-scene.js provide the introduction's unboxed projected 3D software-window illustration, camera math, projected pointer hit testing and interactive orbit. Its illustrated code-to-map sequence uses shaded planes, a cached rounded/beveled Atlas mesh matching the header mark, bounded hover feedback and time-based damping. The logo uses closed front/back caps, outward-normal culling and three cel-shading tones under a fixed world light, prepared on resize. Shared-edge topology is cached once; visible silhouettes get stronger ink and visible cap/slab seams get a finer stroke, without outlining bevel tessellation or hidden edges. Each complete solid receives its fill and contours before nearer solids are painted. This is a lightweight 2D-canvas material treatment; its geometry remains inside the original framing envelope. The logo and two plinth slabs form a cached compound assembly: complete lower slab, upper slab, then depth-ordered complete tiles. This avoids centroid-sorted individual faces cutting through the platform or logo, without per-frame masks or camera fitting. Analytic orbit bounds are cached once; resize creates an expanded canvas and fixed transform around the original logical stage. The caption overlays the lower drawing area without changing layout or intercepting pointer input; a narrow-screen initial fit protects viewport edges. A cancellable five-second idle timer starts a separate 2.4-second shortest-arc return to the home camera, interrupted by pointer/keyboard input and suspended while held, hidden or offscreen. Rendering settles and pauses when hidden or offscreen; reduced motion suppresses hover lift/parallax and connection traversal and makes the idle reset immediate after its delay. It uses no owner data.

The app captures only temporary viewport state, fits on entry and restores the previous transform on exit when map/view/viewport still match; other cases refit the current graph. Dialogs, interactive popovers, graph context menus and connection cancellation keep Escape priority; passive status toasts do not block exit. Side panels and project actions are hidden by presentation rules; existing permissions, notices and graph data are retained. An accessible circular expand/restore icon sits beside Map/Timeline in a shared control row; the caption adapts to the graph pane width. A separate requested state and revision guard keep skipped deferred callbacks from overriding newer click/Escape input, while retaining the original view snapshot until an actual exit. Resize/visibility/motion changes skip only the animation. The existing selection renderer controls a scoped floating Inspector in full-screen mode: absolute positioning and transform/opacity transitions preserve graph geometry, hidden panels are inert, and blank-map selection clearing dismisses it. Its independent in-memory wide state bypasses normal width persistence and graph fitting. Exiting restores normal Inspector presentation and accessibility.

Summary edges aggregate existing relationships; canonical data, exports, saves and edit history never receive the projection. Per-map viewing state resets on map/owner changes.

Its read-only synchronize operation adopts a validated newer library only when the caller is clean and idle; pending writes, open forms/gestures, unsaved work and original recovery bytes cannot be silently replaced. Reconciliation retains each tab's active map and unchanged graph objects. app.js listens to storage/focus/visibility events and retries after writes/dialogs/gestures; it updates the graph, sidebar and Inspector without echo saves or admission, preserves view state, and resets affected local graph histories so Undo cannot overwrite a received edit. - public/src/workspace-navigation.js stores only the selected library, local map ID or verified owner/cloud IDs. - public/src/library-backup.js validates raw or normalized version1 libraries/single maps and creates fresh local copies, stripping cloud associations and unknown metadata. Restore is limited to 100 maps/16 MiB total and each graph's existing bounds. workspace-safety-ui.js owns preview/consent/recovery presentation; local-library.js appends explicit restores under its existing lock against the latest committed library. This is distinct from ordinary guarded editing and cannot silently overwrite a newer library. Unreadable-library replacement requires original-byte download/consent and an unchanged captured snapshot. Queued saves capture serialization once and coalesce superseded intents waiting on a lock; clean navigation needs no library write.
- public/src/workspace-safety.js owns a separate IndexedDB database, atlas-workspace-safety-v1, with scope-indexed recovery and checkpoint records. Drafts use tab-session identity plus independent document keys, retaining duplicated-tab and previous-session versions. Conditional acknowledgement clears only versions covered by a successful restore. Session-storage fallback is refresh-safe only in that tab; blocked/full recovery leaves work in memory and enables a truthful leave/download warning. Draft payloads obey backup bounds; unrecovered versions are retained until explicitly restored and can consume browser quota.

## Data flow

dialog-dismissal.js shares deliberate backdrop dismissal across workspace dialogs and the shared Account/Settings controller. It requires a primary-button press and release outside the dialog bounds, ignores inside-to-outside drags/canceled gestures, and dispatches cancellable cancel before normal close cleanup. Existing import read invalidation, form focus return, stale-preview guards and restore busy cancellation remain authoritative. workspace-safety-ui.js also owns the single sidebar Backups popover: descriptive local-only download/restore actions, optional guidance, native outside/Escape dismissal and viewport-clamped positioning. Recovery remains a directly visible action. No save or destructive confirmation is triggered by dismissal.

Component-result focusing and Fit share app.js's cancellable viewport interpolation. Fit keeps its existing 240ms timing; component/Inspector connection focusing uses420ms with the same final framing. A generation guard plus captured graph/map/view prevents stale motion after a newer target, data replacement or navigation. Existing pan/zoom/drag/full-screen controls cancel it; reduced motion applies immediately and a preference change during motion finishes on the next frame. Timeline retains native smooth scrolling with its reduced-motion fallback. Controlled-clock browser tests exercise intermediate frames, interruption, latest selection, reduced motion and view switching.

A user imports a JSON map or opens a share link. Atlas validates and normalizes that data, computes the layout and renders an interactive graph. Edits are saved in this browser's local storage. Exported JSON can be imported in another browser.

A share link contains a compressed map snapshot in its URL fragment. The browser decodes it locally; recipients edit independent copies. This local sharing mode does not synchronize changes. Optional online workspaces instead use Firebase Authentication and Firestore: the link contains a random workspace ID, the owner saves revisions, and viewers receive the current revision with read-only access. Anyone with a local fragment link can decode its embedded map; anyone with an enabled online link can read its current map. Share only suitable information.

Charts require supporting evidence and are supplied as map data. Atlas does not collect runtime telemetry. External coding agents analyze their own project and produce map files or links; Atlas does not run an AI service or upload source code.

## Hosting

Deploy only public/ to a static host. Relative asset URLs support the landing and workspace routes. The root handles legacy map fragments by forwarding them to the workspace. Static security headers restrict network connections and executable sources. Browser storage is specific to the site's origin.

## Optional cloud boundary

Local storage remains separate from the online library. A sidebar library switch chooses which list to browse, independently of the currently open graph and the future-map saving preference. Per-map actions capture the target origin, map ID and owner identity so opening another row's settings cannot mutate the current graph by accident. Signing in and future-map automatic saving are separate choices. Only explicit preference consent enables automatic future local new/import/fragment uploads; importing from the Cloud Workspace section explicitly uploads that import directly, without a local project. Existing local maps are not migrated. Successful imports shorten the current address after commit. Owners edit normally with autosave, while viewers remain read-only. Firestore stores bounded UTF-8 JSON chunks and owner metadata; rules enforce owner-only modification and allow viewing only an enabled shared workspace's current revision. Revocation or deletion must clear the viewer graph. Account switches cancel pending UI operations and subscriptions. No source repository, analytics or AI request is sent by Atlas.

Cloud creation/final deletion also changes workspaceQuota/{ownerUid} in the same transaction. Rules require exactly one corresponding owned workspace add/remove and enforce the account allowance on creation. A trusted server-only system/workspaceQuota activation record gates membership changes during initial setup. Existing owner registries are seeded from metadata only, preserving graphs and any grandfathered over-limit accounts; browser clients cannot grant themselves allowance overrides; the restricted administrator controls them through the account administration flow below.


## Account administration

`account-access.js` validates claim-derived profile metadata and20/30/40/unlimited allowances. `admin-controller.js` scopes directory reads and allowance updates to the confirmed session, clears rows on identity changes and guards repeat/stale actions. `admin-page.js` renders `/admin` using text nodes and the existing theme/action progress system. The Account panel links there only after a server-confirmed role check.

Firestore `system/adminAccess` is operator-only immutable browser configuration for one Firebase Auth UID. `accountProfiles/{uid}` stores name/email with creation/update timestamps; verified owners can enroll/update only values matching their signed token, and only the administrator can list profiles. `accountLimits/{uid}` stores schemaVersion/maxWorkspaces/updatedBy/updatedAt; owner reads and administrator updates are separate. `workspaceQuota/{uid}` remains the authoritative atomic membership registry and exposes per-account counts to the admin without map graph access. Admission reads the allowance inside the existing create transaction; server quota-add rules independently enforce it. Missing allowance means20; null means unlimited. Reduced allowances affect only new creation and never purge maps. Allowance rule reads occur in the quota write operation, preserving the eight-chunk workspace operation's document-read budget.

`scripts/bootstrap-admin.js` is an operator utility outside the static output. It uses the pinned existing Firebase CLI authentication for a filtered Auth query, metadata-only read-only preview and explicit UID-confirmed setup. `admin-bootstrap-model.js` assembles atomic preconditioned configuration/profile/own-allowance writes, never graph writes. No email/UID-specific administrator identity is bundled into the static application, no service key is shipped, and no privileged Auth-list endpoint is exposed to browsers.
